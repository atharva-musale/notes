# Java

## JDK, JVM and JRE

### JVM (Java Virtual Machine)
- An abstract machine that provides the runtime environment to execute Java bytecode
- Platform-dependent (different implementations for Windows, Linux, macOS)
- Key responsibilities:
  - Loading bytecode
  - Verifying bytecode
  - Executing bytecode
  - Providing runtime environment
- Components:
  - **Class Loader**: Loads class files
  - **Memory Area**: Heap, Stack, Method Area, PC Register, Native Method Stack
  - **Execution Engine**: Interpreter, JIT Compiler, Garbage Collector

### JRE (Java Runtime Environment)
- Provides the environment to run Java applications
- Contains:
  - JVM
  - Core libraries (Java Class Library)
  - Supporting files
- Cannot be used to develop Java applications (no compiler)
- Minimum requirement to run Java programs

### JDK (Java Development Kit)
- Complete development kit for Java
- Contains:
  - JRE (which includes JVM)
  - Development tools (javac, javadoc, jar, etc.)
  - Debugging tools
  - JavaFX (in older versions)
- Required for developing and compiling Java applications

**Relationship**: JDK ⊃ JRE ⊃ JVM

## Strings

### String Immutability
- Strings in Java are **immutable** - once created, cannot be changed
- Benefits:
  - **String Pool**: Allows string literals to be shared in memory
  - **Thread Safety**: Multiple threads can access strings without synchronization
  - **Security**: Prevents malicious code from modifying string values
  - **Hashcode Caching**: Hashcode is cached, improving performance for HashMaps/HashSets

### String Pool (String Intern Pool)
- Special memory region in the **Heap** (before Java 7, it was in PermGen)
- Stores literal string values
- When you create a string literal, JVM checks the pool first
- If the string exists, reference is returned; otherwise, new string is added

```java
String s1 = "Hello";  // Goes to String Pool
String s2 = "Hello";  // References same object from pool
String s3 = new String("Hello");  // Creates new object in heap

s1 == s2  // true (same reference)
s1 == s3  // false (different objects)
s1.equals(s3)  // true (same content)
```

### String vs StringBuilder vs StringBuffer

| Feature | String | StringBuilder | StringBuffer |
|---------|--------|---------------|--------------|
| Mutability | Immutable | Mutable | Mutable |
| Thread Safety | Yes | No | Yes (synchronized) |
| Performance | Slow for concatenation | Fast | Slower than StringBuilder |
| Use Case | Fixed strings | Single-threaded string manipulation | Multi-threaded string manipulation |

### Common String Methods
```java
length()                    // Returns string length
charAt(int index)           // Returns character at index
substring(int begin, int end)  // Extracts substring
concat(String str)          // Concatenates strings
indexOf(String str)         // Returns first occurrence index
replace(char old, char new) // Replaces characters
split(String regex)         // Splits string by delimiter
trim()                      // Removes leading/trailing whitespace
toLowerCase() / toUpperCase()  // Case conversion
equals() / equalsIgnoreCase()  // Content comparison
```

## Class files and Java files

### Java Source Files (.java)
- Human-readable text files containing Java source code
- Must have `.java` extension
- File name must match the public class name. (`MyClass.java` for `class MyClass`)
- Can contain:
  - One public class (optional)
  - Multiple non-public classes
  - Package declaration
  - Import statements

### Java Class Files (.class)
- Binary files containing Java bytecode
- Generated by the Java compiler (`javac`)
- Platform-independent bytecode that JVM can execute
- One `.class` file is generated for each class/interface in the source file
- Contains:
  - Bytecode instructions
  - Constant pool (literals, type references, field/method references)
  - Field information
  - Method information
  - Attributes (metadata)

### Compilation Process
```
Source Code (.java) → javac compiler → Bytecode (.class) → JVM → Machine Code
```

1. **Write**: Developer writes `.java` source file
2. **Compile**: `javac MyClass.java` compiles to `MyClass.class`
3. **Load**: Class Loader loads `.class` file into memory
4. **Verify**: Bytecode Verifier ensures code safety
5. **Execute**: Execution Engine (Interpreter/JIT) executes bytecode

### Key Points
- **One-to-Many**: One `.java` file can produce multiple `.class` files (inner classes, anonymous classes)
- **Bytecode**: `.class` files contain platform-independent bytecode
- **Decompilation**: `.class` files can be decompiled back to Java source (though without comments/formatting)
- **Version Compatibility**: `.class` files have a version number; older JVMs cannot run newer class files

### Example
```java
// MyClass.java
public class MyClass {
  class InnerClass { }
  static class StaticNested { }
}
```
Produces three `.class` files:
- `MyClass.class`
- `MyClass$InnerClass.class`
- `MyClass$StaticNested.class`

## Class loaders

### What is a Class Loader?
- Part of JVM responsible for loading class files into memory
- Loads classes dynamically at runtime (not all at once)
- Follows **delegation model** and **lazy loading**

### Types of Class Loaders

#### 1. Bootstrap Class Loader
- The parent of all class loaders
- Loads core Java classes from `rt.jar` (or module system in Java 9+)
- Located in `JAVA_HOME/jre/lib`
- Written in native code (C/C++)
- Loads classes like `java.lang.*`, `java.util.*`

#### 2. Extension Class Loader
- Child of Bootstrap Class Loader
- Loads classes from the extensions directory (`JAVA_HOME/jre/lib/ext`)
- Also loads classes from directories specified by `java.ext.dirs` system property
- Implemented by `sun.misc.Launcher$ExtClassLoader`

#### 3. Application/System Class Loader
- Child of Extension Class Loader
- Loads classes from the application classpath
- Loads classes from paths specified by `-classpath` or `CLASSPATH` environment variable
- Implemented by `sun.misc.Launcher$AppClassLoader`

### Class Loader Delegation Model
- When a class needs to be loaded, the request is delegated to parent class loader first
- Flow: Application → Extension → Bootstrap
- If parent cannot find the class, then child attempts to load it
- Prevents loading core classes multiple times
- Ensures core Java classes are loaded by Bootstrap Class Loader

```
Request to load a class
        ↓
Application Class Loader (checks cache)
        ↓ (delegates)
Extension Class Loader (checks cache)
        ↓ (delegates)
Bootstrap Class Loader (checks cache)
        ↓
Loads or throws ClassNotFoundException
```

### Custom Class Loaders
- You can create custom class loaders by extending `ClassLoader`
- Use cases:
  - Loading classes from non-standard sources (network, database)
  - Implementing hot deployment
  - Loading encrypted classes
  - Isolating class versions

```java
public class CustomClassLoader extends ClassLoader {
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        byte[] classData = loadClassData(name);
        return defineClass(name, classData, 0, classData.length);
    }
    
    private byte[] loadClassData(String name) {
        // Load class bytes from custom source
        return null;
    }
}
```

## Static keyword and static block

### Static Variables (Class Variables)
- Variables declared with `static` keyword belong to the class, not instances
- Shared among all instances of the class
- Allocated memory once when class is loaded
- Can be accessed without creating an object

```java
public class Counter {
    static int count = 0;  // Static variable
    int id;                // Instance variable
    
    Counter() {
        count++;           // Shared across all instances
        id = count;        // Unique to each instance
    }
}

Counter c1 = new Counter();  // count = 1
Counter c2 = new Counter();  // count = 2
System.out.println(Counter.count);  // 2 (access without object)
```

### Static Methods
- Methods declared with `static` keyword belong to the class
- Can be called without creating an instance of the class
- Can only access static variables and other static methods directly
- Cannot use `this` or `super` keywords

```java
public class MathUtils {
    static int add(int a, int b) {
        return a + b;
    }
    
    static int square(int n) {
        return n * n;
    }
}

// Call without creating object
int result = MathUtils.add(5, 3);  // 8
```

**Restrictions:**
- Cannot access non-static (instance) variables directly
- Cannot call non-static methods directly
- Cannot use `this` reference (no instance context)

### Static Blocks
- Block of code that executes when the class is loaded into memory
- Executes only once, before any constructor or main method
- Used for static initialization of complex logic
- Multiple static blocks execute in order they appear

```java
public class Database {
    static Connection connection;
    static String url;
    
    // Static block - runs once when class loads
    static {
        System.out.println("Initializing database...");
        url = "jdbc:mysql://localhost:3306/mydb";
        connection = DriverManager.getConnection(url);
    }
    
    // Another static block
    static {
        System.out.println("Database initialized");
    }
}
```

**Execution order:**
1. Static variables initialization
2. Static blocks (in order)
3. Instance variables initialization
4. Instance blocks
5. Constructor

```java
public class Demo {
    static int x = 10;           // 1. Static variable
    int y = 20;                  // 3. Instance variable
    
    static {                     // 2. Static block
        System.out.println("Static block: x = " + x);
    }
    
    {                            // 4. Instance block
        System.out.println("Instance block: y = " + y);
    }
    
    Demo() {                     // 5. Constructor
        System.out.println("Constructor");
    }
    
    public static void main(String[] args) {
        new Demo();
    }
}
// Output:
// Static block: x = 10
// Instance block: y = 20
// Constructor
```

### Static Nested Classes
- A static class defined inside another class
- Can be instantiated without an instance of outer class
- Can only access static members of outer class

```java
public class Outer {
    static int x = 10;
    int y = 20;
    
    static class StaticNested {
        void display() {
            System.out.println(x);  // OK - static member
            // System.out.println(y);  // Error - non-static member
        }
    }
}

// Usage
Outer.StaticNested nested = new Outer.StaticNested();
nested.display();
```

### Common Use Cases

**1. Utility/Helper classes:**
```java
public class StringUtils {
    private StringUtils() {}  // Prevent instantiation
    
    public static boolean isEmpty(String str) {
        return str == null || str.isEmpty();
    }
    
    public static String reverse(String str) {
        return new StringBuilder(str).reverse().toString();
    }
}
```

**2. Constants:**
```java
public class Constants {
    public static final double PI = 3.14159;
    public static final int MAX_SIZE = 100;
    public static final String APP_NAME = "MyApp";
}
```

**3. Singleton pattern:**
```java
public class Singleton {
    private static Singleton instance;
    
    private Singleton() {}  // Private constructor
    
    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

**4. Factory methods:**
```java
public class Employee {
    private String name;
    private double salary;
    
    private Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }
    
    public static Employee createManager(String name) {
        return new Employee(name, 100000);
    }
    
    public static Employee createDeveloper(String name) {
        return new Employee(name, 80000);
    }
}
```

### Key Points to Remember
- Static members are loaded when class is loaded (before any object creation)
- Static members belong to class, not objects
- Static methods can't access instance members directly
- Static blocks execute once during class loading
- Use static for utility methods, constants, and shared data
- `static final` creates constants
- Avoid overusing static - can make testing difficult

## Object oriented programming basics

### Four Pillars of OOP

#### 1. Encapsulation
- Bundling data (fields) and methods that operate on that data within a single unit (class)
- Hiding internal implementation details from outside world
- Achieved using access modifiers (`private`, `protected`, `public`)
- Provides data protection and controlled access through getters/setters

```java
public class BankAccount {
    private double balance;  // Hidden from outside
    
    public double getBalance() {
        return balance;  // Controlled read access
    }
    
    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;  // Controlled write with validation
        }
    }
}
```

#### 2. Inheritance
- Mechanism where a new class (subclass/child) derives properties and behaviors from an existing class (superclass/parent)
- Promotes code reusability and establishes IS-A relationship
- Uses `extends` keyword
- Java supports single inheritance (one parent) but multiple levels of inheritance

```java
public class Animal {
    protected String name;
    
    public void eat() {
        System.out.println("Animal is eating");
    }
}

public class Dog extends Animal {
    public void bark() {
        System.out.println("Dog is barking");
    }
}
```

**Types of Inheritance:**
- **Single**: Class B extends Class A
- **Multilevel**: Class C extends B, which extends A
- **Hierarchical**: Multiple classes extend the same parent
- **Multiple** (via interfaces): Class implements multiple interfaces

#### 3. Polymorphism
- Ability of an object to take many forms
- Same method behaves differently based on the object calling it

**Compile-time Polymorphism (Method Overloading)**
- Same method name with different parameters in the same class
```java
public class Calculator {
    public int add(int a, int b) { return a + b; }
    public double add(double a, double b) { return a + b; }
    public int add(int a, int b, int c) { return a + b + c; }
}
```

**Runtime Polymorphism (Method Overriding)**
- Subclass provides specific implementation of a method already defined in superclass
- Requires inheritance and `@Override` annotation (optional but recommended)
```java
public class Animal {
    public void makeSound() {
        System.out.println("Animal sound");
    }
}

public class Dog extends Animal {
    @Override
    public void makeSound() {
        System.out.println("Bark");
    }
}

Animal myDog = new Dog();
myDog.makeSound();  // Outputs: Bark (runtime polymorphism)
```

#### 4. Abstraction
- Hiding complex implementation details and showing only essential features
- Achieved through abstract classes and interfaces
- Focuses on WHAT an object does rather than HOW

**Abstract Class:**
- Cannot be instantiated
- Can have both abstract (no body) and concrete (with body) methods
- Can have constructors, instance variables, and any access modifiers

```java
public abstract class Shape {
    protected String color;
    
    public abstract double calculateArea();  // Abstract method
    
    public void displayColor() {  // Concrete method
        System.out.println("Color: " + color);
    }
}

public class Circle extends Shape {
    private double radius;
    
    @Override
    public double calculateArea() {
        return Math.PI * radius * radius;
    }
}
```

**Interface:**
- 100% abstraction (before Java 8)
- All methods are implicitly `public abstract` (before Java 8)
- All variables are implicitly `public static final`
- Since Java 8: can have default and static methods
- Since Java 9: can have private methods

```java
public interface Drawable {
    void draw();  // Abstract method
    
    default void print() {  // Default method (Java 8+)
        System.out.println("Printing...");
    }
}
```

### Class Relationships

#### IS-A Relationship (Inheritance)
- Represents inheritance
- "Dog IS-A Animal"
- Uses `extends` keyword

#### HAS-A Relationship (Composition/Aggregation)
- Object contains another object as a member
- "Car HAS-A Engine"
- Promotes code reuse without inheritance

```java
public class Engine {
    public void start() { }
}

public class Car {
    private Engine engine;  // HAS-A relationship
    
    public Car() {
        this.engine = new Engine();
    }
}
```

### Constructor Rules
- Same name as class, no return type
- Called automatically when object is created
- If no constructor is defined, Java provides a default no-arg constructor
- Can be overloaded
- First line can be `super()` or `this()` to call parent or another constructor

### Method Overriding vs Overloading

| Feature | Overriding | Overloading |
|---------|-----------|-------------|
| Definition | Same method signature in subclass | Same method name, different parameters |
| Polymorphism | Runtime | Compile-time |
| Class | Different classes (inheritance) | Same class |
| Return Type | Must be same or covariant | Can be different |
| Access Modifier | Cannot be more restrictive | Can be any |
| Example | `@Override` annotation | Multiple constructors |


## Packages

### What is a Package?
- A namespace that organizes related classes and interfaces
- Provides access protection and namespace management
- Helps avoid naming conflicts
- Creates a hierarchical structure for organizing code

### Types of Packages

#### 1. Built-in Packages
- Pre-defined packages provided by Java
- Examples:
  - `java.lang` - Fundamental classes (String, Math, System) - imported automatically
  - `java.util` - Utility classes (Collections, Date, Scanner)
  - `java.io` - Input/output operations
  - `java.net` - Networking
  - `java.sql` - Database connectivity
  - `java.awt` / `javax.swing` - GUI components

#### 2. User-defined Packages
- Created by developers
- Typically follow reverse domain naming convention: `com.company.project.module`

### Creating a Package

```java
// File: com/mycompany/project/MyClass.java
package com.mycompany.project;  // Must be first statement

public class MyClass {
  public void display() {
    System.out.println("Hello from package");
  }
}
```

### Using Packages

#### Import Specific Class
```java
import java.util.ArrayList;

public class Test {
  public static void main(String[] args) {
    ArrayList<String> list = new ArrayList<>();
  }
}
```

#### Import All Classes from Package
```java
import java.util.*;  // Imports all classes from java.util
```

#### Fully Qualified Name (No Import)
```java
public class Test {
  public static void main(String[] args) {
    java.util.ArrayList<String> list = new java.util.ArrayList<>();
  }
}
```

#### Static Import
```java
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;

public class Test {
    public static void main(String[] args) {
        double area = PI * 5 * 5;  // No need for Math.PI
        double root = sqrt(16);     // No need for Math.sqrt()
    }
}
```

### Package Naming Conventions
- All lowercase letters
- Reverse domain name: `com.company.product`
- Subpackages for logical grouping:
  - `com.company.product.model`
  - `com.company.product.service`
  - `com.company.product.controller`
  - `com.company.product.util`

### Package Access
- Classes/members without access modifier have **package-private** (default) access
- Accessible only within the same package
```java
package com.example;

class PackageClass {  // Package-private (no public)
  void display() {  // Package-private method
    System.out.println("Package access");
  }
}
```

### Compilation and Execution with Packages

**Compile:**
```bash
javac -d . MyClass.java  # -d specifies destination for .class files
```

**Run:**
```bash
java com.mycompany.project.MyClass
```

### Key Points
- Package declaration must be the first statement (except comments)
- Only one package declaration per source file
- `java.lang` package is imported automatically
- A class can import multiple packages
- Packages create a directory structure matching the package name
- Use packages to organize large projects and avoid name conflicts
- Package hierarchy doesn't imply class hierarchy (no inheritance relationship)

## Interfaces and Enums

### Interfaces

#### What is an Interface?
- A reference type that defines a contract - a set of method signatures that implementing classes must provide
- Achieves 100% abstraction (before Java 8)
- Supports multiple inheritance (a class can implement multiple interfaces)
- Defines WHAT a class should do, not HOW

#### Example
```java
public interface Animal {
  // Abstract methods (implicitly public abstract)
  void eat();
  void sleep();
  
  // Constants (implicitly public static final)
  int MAX_AGE = 100;
}

public class Dog implements Animal {
  @Override
  public void eat() {
    System.out.println("Dog is eating");
  }
  
  @Override
  public void sleep() {
    System.out.println("Dog is sleeping");
  }
}
```

#### Interface Features by Java Version

**Java 7 and Earlier:**
- Only abstract methods (implicitly `public abstract`)
- Only constants (implicitly `public static final`)
- No method implementations

**Java 8:**
- **Default methods** - methods with implementation
  ```java
  public interface Vehicle {
    default void start() {
      System.out.println("Vehicle starting");
    }
  }
  ```
- **Static methods** - utility methods in interfaces
  ```java
  public interface Calculator {
    static int add(int a, int b) {
      return a + b;
    }
  }
  // Call: Calculator.add(5, 3);
  ```

**Java 9:**
- **Private methods** - helper methods for default methods
  ```java
  public interface MyInterface {
    default void method1() {
      commonLogic();
    }
    
    default void method2() {
      commonLogic();
    }
    
    private void commonLogic() {
      // Shared logic
    }
  }
  ```

### Functional Interfaces

A **functional interface** is an interface that has exactly one abstract method. This single abstract method represents a specific behavior or action that needs to be performed.

**Key Characteristics:**
- Contains exactly **one abstract method** (SAM - Single Abstract Method)
- Can have any number of default or static methods
- Annotated with `@FunctionalInterface` (optional but recommended for compile-time checking)
- Can be used with **lambda expressions** and method references

#### What is a Lambda Expression?

A **lambda expression** is a concise way to represent an anonymous function (a function without a name). It provides a clear and compact way to write inline implementations of functional interfaces without creating separate classes or using verbose anonymous inner classes.

**Syntax:** `(parameters) -> expression` or `(parameters) -> { statements; }`

**Example:**
```java
// Old way: Using anonymous inner class (verbose)
Runnable runnable1 = new Runnable() {
    @Override
    public void run() {
        System.out.println("Running...");
    }
};

// New way: Using lambda expression (concise)
Runnable runnable2 = () -> System.out.println("Running...");
```

#### Why Lambda Expressions Work Only with Functional Interfaces

Lambda expressions work only with functional interfaces because:

1. **Single Target Method**: Since a functional interface has exactly one abstract method, the Java compiler knows which method the lambda expression is implementing. There's no ambiguity.

2. **Type Inference**: The compiler can infer the types of parameters and return type from the functional interface's single abstract method signature.

3. **Clear Mapping**: One lambda expression maps to one method, making the code unambiguous and type-safe.

**Example:**
```java
// If an interface had 2+ abstract methods, which one would the lambda implement?
interface MultiMethod {
  void method1();
  void method2();  // Compiler wouldn't know which method to use!
}
// MultiMethod obj = () -> System.out.println("Which method?"); // ERROR!

// With functional interface, it's clear:
@FunctionalInterface
interface SingleMethod {
  void execute();  // Only one method - lambda targets this
}
SingleMethod obj = () -> System.out.println("Clear!"); // Works!
```

#### Complete Example

```java
@FunctionalInterface
public interface Comparator<T> {
  int compare(T o1, T o2);  // Single abstract method
  
  // Can have default and static methods
  default Comparator<T> reversed() {
    return (o1, o2) -> compare(o2, o1);
  }
}

// Traditional anonymous inner class (verbose)
Comparator<String> comp1 = new Comparator<String>() {
    @Override
    public int compare(String s1, String s2) {
      return s1.compareTo(s2);
    }
};

// Lambda expression (concise) - implements the compare() method
Comparator<String> comp2 = (s1, s2) -> s1.compareTo(s2);
```

**Common Functional Interfaces:**
- `Runnable` - `void run()`
- `Callable<V>` - `V call()`
- `Comparator<T>` - `int compare(T o1, T o2)`
- `Predicate<T>` - `boolean test(T t)`
- `Function<T,R>` - `R apply(T t)`
- `Consumer<T>` - `void accept(T t)`
- `Supplier<T>` - `T get()`

#### Interface vs Abstract Class

| Feature | Interface | Abstract Class |
|---------|-----------|----------------|
| Multiple Inheritance | Yes | No |
| Method Implementation | Default/Static (Java 8+) | Both abstract and concrete |
| Variables | Only constants (public static final) | Any type of variables |
| Constructors | No | Yes |
| Access Modifiers | Methods are public | Can be any |
| When to Use | Define capability (can-do relationship) | Share code among related classes |

#### Marker Interfaces
- Interfaces with no methods
- Used to mark classes with special behavior
- JVM or frameworks treat them specially

```java
public interface Serializable {
    // No methods - marker interface
}

public class User implements Serializable {
    // Now this class can be serialized
}
```

**Common Marker Interfaces:**
- `Serializable` - Object can be serialized
- `Cloneable` - Object can be cloned
- `Remote` - Object can be invoked remotely

### Enums

#### What is an Enum?
- Special class type that represents a group of constants
- Type-safe alternative to integer constants
- Each enum constant is an instance of the enum type
- Implicitly `public static final`

#### Basic Enum Declaration
```java
public enum Day {
    MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
}

// Usage
Day today = Day.MONDAY;
System.out.println(today);  // MONDAY
```

#### Enum with Values
```java
public enum Size {
    SMALL(10), MEDIUM(20), LARGE(30), XLARGE(40);
    
    private final int value;
    
    // Constructor (always private or package-private)
    Size(int value) {
        this.value = value;
    }
    
    public int getValue() {
        return value;
    }
}

// Usage
Size size = Size.MEDIUM;
System.out.println(size.getValue());  // 20
```

#### Enum with Methods
```java
public enum Operation {
    ADD {
        @Override
        public double apply(double x, double y) {
            return x + y;
        }
    },
    SUBTRACT {
        @Override
        public double apply(double x, double y) {
            return x - y;
        }
    },
    MULTIPLY {
        @Override
        public double apply(double x, double y) {
            return x * y;
        }
    };
    
    public abstract double apply(double x, double y);
}

// Usage
double result = Operation.ADD.apply(5, 3);  // 8
```

#### Built-in Enum Methods
```java
public enum Color {
    RED, GREEN, BLUE
}

// Static methods
Color[] colors = Color.values();           // Returns array of all enum constants
Color color = Color.valueOf("RED");        // Returns enum constant by name
Color red = Enum.valueOf(Color.class, "RED");

// Instance methods
String name = Color.RED.name();            // "RED"
int ordinal = Color.GREEN.ordinal();       // 1 (position in enum)
```

#### Enum with Constructor and Multiple Values
```java
public enum Planet {
    MERCURY(3.303e+23, 2.4397e6),
    VENUS(4.869e+24, 6.0518e6),
    EARTH(5.976e+24, 6.37814e6),
    MARS(6.421e+23, 3.3972e6);
    
    private final double mass;   // in kilograms
    private final double radius; // in meters
    
    Planet(double mass, double radius) {
        this.mass = mass;
        this.radius = radius;
    }
    
    public double getMass() { return mass; }
    public double getRadius() { return radius; }
    
    public double surfaceGravity() {
        final double G = 6.67300E-11;
        return G * mass / (radius * radius);
    }
}

// Usage
```

## Exceptions

### What is an Exception?
- An **exception** is an unexpected or abnormal event that occurs during program execution, disrupting normal flow
- When an exception occurs, Java creates an **exception object** containing information about the error
- Exceptions help handle runtime errors gracefully without crashing the program

**Think of it like this:** If you're driving and hit a pothole (error), you don't abandon the car - you handle it by steering carefully. Similarly, exceptions let your program handle problems without crashing.

### Exception Hierarchy

```
        Object
          ↓
      Throwable
      ↙       ↘
  Error      Exception
              ↙        ↘
    IOException    RuntimeException
                    (ArithmeticException,
                    NullPointerException, etc.)
```

#### 1. Throwable
- Root class for all errors and exceptions
- Two main subclasses: **Error** and **Exception**

#### 2. Error
- Serious problems that applications **should not** try to catch
- Usually external to the application
- Examples:
  - `OutOfMemoryError` - JVM runs out of memory
  - `StackOverflowError` - Too many nested method calls
  - `VirtualMachineError` - JVM has crashed

#### 3. Exception
- Problems that applications **can and should** handle
- Two categories: **Checked** and **Unchecked**

### Types of Exceptions

#### Checked Exceptions (Compile-Time Exceptions)
- Exceptions that **must** be handled at compile time
- Compiler forces you to handle them using `try-catch` or declare with `throws`
- Represent predictable problems that can occur

**Common Checked Exceptions:**
- `IOException` - Input/output operations fail
- `FileNotFoundException` - File doesn't exist
- `SQLException` - Database access error
- `ClassNotFoundException` - Class not found
- `InterruptedException` - Thread is interrupted

```java
// Must handle with try-catch
public void readFile() {
    try {
        FileReader file = new FileReader("data.txt");
    } catch (FileNotFoundException e) {
        System.out.println("File not found!");
    }
}

// OR declare with throws
public void readFile() throws FileNotFoundException {
    FileReader file = new FileReader("data.txt");
}
```

#### Unchecked Exceptions (Runtime Exceptions)
- Exceptions that occur at runtime
- **Not** required to be caught or declared
- Usually caused by programming errors (bugs)
- All subclasses of `RuntimeException`

**Common Unchecked Exceptions:**
- `NullPointerException` - Accessing null object
- `ArithmeticException` - Math errors (divide by zero)
- `ArrayIndexOutOfBoundsException` - Invalid array index
- `NumberFormatException` - Invalid string to number conversion
- `IllegalArgumentException` - Invalid method argument
- `ClassCastException` - Invalid type casting

```java
public class ExceptionExamples {
  public static void main(String[] args) {
    // NullPointerException
    String str = null;
    // System.out.println(str.length()); // Error!
    
    // ArithmeticException
    // int result = 10 / 0; // Error!
    
    // ArrayIndexOutOfBoundsException
    int[] arr = {1, 2, 3};
    // System.out.println(arr[5]); // Error!
    
    // NumberFormatException
    // int num = Integer.parseInt("abc"); // Error!
  }
}
```

### Exception Handling Keywords

#### 1. try
- Block of code that might throw an exception
- Must be followed by `catch` or `finally` or both

```java
try {
  // Code that might throw exception
  int result = 10 / 0;
}
```

#### 2. catch
- Catches and handles specific exception
- Can have multiple catch blocks for different exceptions
- Must come after `try`

```java
try {
  int result = 10 / 0;
} catch (ArithmeticException e) {
  System.out.println("Cannot divide by zero!");
}
```

#### 3. finally
- Always executes, whether exception occurs or not
- Used for cleanup (closing files, database connections)
- Optional but recommended for resource management

```java
FileReader file = null;
try {
  file = new FileReader("data.txt");
  // Read file
} catch (IOException e) {
  System.out.println("Error reading file");
} finally {
  if (file != null) {
    try {
      file.close(); // Always close the file
    } catch (IOException e) {
      e.printStackTrace();
    }
  }
}
```

#### 4. throw
- Used to explicitly throw an exception
- Can throw any `Throwable` object

```java
public void setAge(int age) {
  if (age < 0) {
    throw new IllegalArgumentException("Age cannot be negative");
  }
  this.age = age;
}
```

#### 5. throws
- Declares that a method might throw exceptions
- Used in method signature
- Caller must handle the exception

```java
public void readFile(String path) throws IOException {
  FileReader file = new FileReader(path);
  // Caller must handle IOException
}
```

### Multiple Catch Blocks

You can catch different exceptions separately:

```java
try {
  String str = args[0];        // ArrayIndexOutOfBoundsException
  int num = Integer.parseInt(str);  // NumberFormatException
  int result = 100 / num;      // ArithmeticException
} catch (ArrayIndexOutOfBoundsException e) {
  System.out.println("Please provide an argument");
} catch (NumberFormatException e) {
  System.out.println("Argument must be a number");
} catch (ArithmeticException e) {
  System.out.println("Number cannot be zero");
}
```

**Multi-catch (Java 7+):**
```java
try {
  // Some code
} catch (IOException | SQLException e) {
  // Handle both exceptions the same way
  System.out.println("Error occurred: " + e.getMessage());
}
```

**Catch Order Rules:**
- More specific exceptions first, generic ones last
- Child exception classes before parent classes
```java
try {
  // Code
} catch (FileNotFoundException e) {
  // Specific exception first
} catch (IOException e) {
  // Parent exception later
} catch (Exception e) {
  // Most generic last
}
```

### try-with-resources (Java 7+)

Automatically closes resources (files, connections) that implement `AutoCloseable`:

```java
// Old way - manual cleanup
BufferedReader br = null;
try {
  br = new BufferedReader(new FileReader("file.txt"));
  String line = br.readLine();
} catch (IOException e) {
  e.printStackTrace();
} finally {
  if (br != null) {
    try {
      br.close();
    } catch (IOException e) {
      e.printStackTrace();
    }
  }
}

// New way - automatic cleanup
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
  String line = br.readLine();
} catch (IOException e) {
  e.printStackTrace();
}
// br is automatically closed, even if exception occurs
```

**Multiple resources:**
```java
try (FileReader fr = new FileReader("input.txt");
  BufferedReader br = new BufferedReader(fr);
  FileWriter fw = new FileWriter("output.txt")) {
  // Use resources
} catch (IOException e) {
  e.printStackTrace();
}
// All resources closed automatically
```

Common methods available on exception objects:

```java

  int result = 10 / 0;
} catch (ArithmeticException e) {
```


### Chained Exceptions

Link exceptions to show the root cause:

```java
try {
    // Lower level operation
    connectToDatabase();
} catch (SQLException e) {
    // Wrap in higher level exception with cause
    throw new RuntimeException("Failed to initialize application", e);
}
```

### Best Practices

#### 1. Be Specific
```java
// ❌ Too generic
try {
    // code
} catch (Exception e) {
    // Catches everything, hard to debug
}

// ✅ Specific
try {
    // code
} catch (FileNotFoundException e) {
    // Handle specific problem
} catch (IOException e) {
    // Handle other IO problems
}
```

#### 2. Don't Ignore Exceptions
```java
// ❌ Bad - swallowing exceptions
try {
    // code
} catch (Exception e) {
    // Silent failure
}

// ✅ Good - at least log it
try {
    // code
} catch (Exception e) {
    logger.error("Error occurred", e);
    // or e.printStackTrace();
}
```

#### 3. Use finally for Cleanup
```java
// ✅ Good
Connection conn = null;
try {
    conn = getConnection();
    // Use connection
} catch (SQLException e) {
    e.printStackTrace();
} finally {
    if (conn != null) {
        conn.close(); // Always close
    }
}
```

#### 4. Don't Use Exceptions for Control Flow
```java
// ❌ Bad
try {
  int i = 0;
  while (true) {
    System.out.println(arr[i++]);
  }
} catch (ArrayIndexOutOfBoundsException e) {
  // Used to break loop
}

// ✅ Good
for (int i = 0; i < arr.length; i++) {
  System.out.println(arr[i]);
}
```

#### 5. Create Meaningful Custom Exceptions
```java
// ✅ Good - clear and specific
public class UserNotFoundException extends Exception {
  private String userId;
  
  public UserNotFoundException(String userId) {
    super("User not found with ID: " + userId);
    this.userId = userId;
  }
  
  public String getUserId() {
    return userId;
  }
}
```

#### 6. Document Exceptions
```java
/**
 * Transfers money between accounts.
 * 
 * @param fromAccount Source account
 * @param toAccount Destination account
 * @param amount Amount to transfer
 * @throws InsufficientBalanceException if source account lacks funds
 * @throws InvalidAccountException if account is inactive
 */
public void transfer(Account fromAccount, Account toAccount, double amount) 
    throws InsufficientBalanceException, InvalidAccountException {
    // Implementation
}
```

#### Scenario 1: Reading a File

```java
  try (Connection conn = DriverManager.getConnection(DB_URL);
    Statement stmt = conn.createStatement();
    ResultSet rs = stmt.executeQuery("SELECT * FROM users")) {
```

### Key Takeaways

- **Use checked exceptions** for recoverable conditions (file not found, network error)
- **Use unchecked exceptions** for programming errors (null pointer, invalid arguments)
- **Always clean up resources** using finally or try-with-resources
- **Be specific** when catching exceptions - catch what you can handle
- **Never leave catch blocks empty** - at minimum, log the error
- **Create custom exceptions** when built-in ones don't fit your needs
- **Document exceptions** in method signatures and JavaDoc
- **Don't overuse exceptions** - they're for exceptional situations, not control flow

## Threads

### What are Threads?

A thread is a lightweight subprocess, the smallest unit of processing. Java is a multithreaded programming language, which means we can develop programs that execute multiple tasks simultaneously. Each task runs in its own thread.

**Real-world analogy**: Think of a restaurant kitchen. The head chef (main program) can have multiple assistants (threads) working on different tasks at the same time - one chopping vegetables, another cooking pasta, another plating dishes.

### Why Use Threads?

- **Better performance**: Multiple operations can run simultaneously
- **Responsive applications**: UI remains responsive while background work happens
- **Efficient resource usage**: Better utilization of CPU cores
- **Concurrent operations**: Handle multiple client requests at once (like in servers)

### Creating Threads

There are two main ways to create threads in Java:

#### Method 1: Extending the Thread class

```java
class MyThread extends Thread {
    public void run() {
        // Code that runs in the thread
        for (int i = 1; i <= 5; i++) {
            System.out.println("Thread: " + i);
            try {
                Thread.sleep(1000); // Pause for 1 second
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}

// Using the thread
public class Main {
    public static void main(String[] args) {
        MyThread thread1 = new MyThread();
        thread1.start(); // Starts the thread
    }
}
```

#### Method 2: Implementing the Runnable interface (Preferred)

```java
class MyRunnable implements Runnable {
    public void run() {
        // Code that runs in the thread
        for (int i = 1; i <= 5; i++) {
            System.out.println("Runnable: " + i);
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}

// Using the runnable
public class Main {
    public static void main(String[] args) {
        MyRunnable myRunnable = new MyRunnable();
        Thread thread = new Thread(myRunnable);
        thread.start();
    }
}
```

**Why is Runnable preferred?**
- Java doesn't support multiple inheritance, so if you extend Thread, you can't extend another class
- Runnable separates the task from the thread mechanism (better design)
- You can implement multiple interfaces

### Thread Lifecycle

A thread goes through several states:

1. **New**: Thread is created but not yet started
2. **Runnable**: Thread is ready to run and waiting for CPU time
3. **Running**: Thread is currently executing
4. **Blocked/Waiting**: Thread is waiting for a resource or another thread
5. **Terminated**: Thread has completed execution

```java
Thread thread = new Thread(myRunnable); // NEW
thread.start();                         // RUNNABLE
// When CPU picks it up -> RUNNING
// When it finishes -> TERMINATED
```

### Important Thread Methods

```java
// Starting a thread
thread.start(); // Begins execution

// Pausing execution
Thread.sleep(1000); // Sleep for 1 second (1000 milliseconds)

// Getting thread information
thread.getName();        // Get thread name
thread.setName("MyThread"); // Set thread name
thread.getId();          // Get unique thread ID
Thread.currentThread();  // Get reference to currently executing thread

// Waiting for a thread to finish
thread.join(); // Wait for this thread to complete before continuing

// Checking thread state
thread.isAlive(); // Returns true if thread is still running
```

### Multiple Threads Example

```java
class Task implements Runnable {
    private String taskName;
    
    public Task(String name) {
        this.taskName = name;
    }
    
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println(taskName + " - Step " + i);
            try {
                Thread.sleep(500);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        System.out.println(taskName + " completed!");
    }
}

public class Main {
    public static void main(String[] args) {
        Thread t1 = new Thread(new Task("Task-A"));
        Thread t2 = new Thread(new Task("Task-B"));
        Thread t3 = new Thread(new Task("Task-C"));
        
        t1.start();
        t2.start();
        t3.start();
        
        // Output will be interleaved - all tasks run simultaneously
    }
}
```

### Thread Priority

Threads have priorities (1 to 10) that suggest to the scheduler which threads should get CPU time first:

```java
thread.setPriority(Thread.MIN_PRIORITY);  // 1
thread.setPriority(Thread.NORM_PRIORITY); // 5 (default)
thread.setPriority(Thread.MAX_PRIORITY);  // 10

// Higher priority threads are more likely to be executed first
// But this is just a hint - not guaranteed
```

### Daemon Threads

Daemon threads are background threads that don't prevent the JVM from exiting:

```java
Thread daemon = new Thread(new MyRunnable());
daemon.setDaemon(true); // Must be called before start()
daemon.start();

// JVM exits when only daemon threads are running
// Examples: Garbage collector, monitoring threads
```

### Common Pitfalls

1. **Calling run() instead of start()**
   ```java
   thread.run();  // WRONG: Just calls the method, no new thread
   thread.start(); // CORRECT: Creates and starts a new thread
   ```

2. **Starting a thread twice**
   ```java
   thread.start();
   thread.start(); // Throws IllegalThreadStateException
   ```

3. **Not handling InterruptedException**
   ```java
   // Always handle when using sleep() or join()
   try {
       Thread.sleep(1000);
   } catch (InterruptedException e) {
       e.printStackTrace();
   }
   ```

### Thread Synchronization Basics

When multiple threads access shared resources, you need synchronization to avoid conflicts:

```java
class Counter {
    private int count = 0;
    
    // synchronized method - only one thread can execute at a time
    public synchronized void increment() {
        count++;
    }
    
    public synchronized int getCount() {
        return count;
    }
}

// Without synchronized, multiple threads could interfere with each other
// causing incorrect results
```

### Lambda with Threads

Modern Java allows using lambda expressions with threads:

```java
// Instead of creating a class
Thread thread = new Thread(() -> {
    System.out.println("Running in a thread!");
    for (int i = 1; i <= 5; i++) {
        System.out.println("Count: " + i);
    }
});
thread.start();
```

### Best Practices

- **Use thread pools** for managing multiple threads efficiently (ExecutorService)
- **Avoid shared mutable state** when possible
- **Always synchronize** access to shared resources
- **Use higher-level concurrency utilities** from java.util.concurrent package
- **Handle interruptions** properly
- **Don't catch ThreadDeath** - let threads die naturally
- **Name your threads** for easier debugging

### When to Use Threads

Good use cases:
- Running background tasks (file downloads, data processing)
- Keeping UI responsive while doing heavy computation
- Handling multiple client connections in servers
- Parallel processing of independent tasks

Avoid threads when:
- Task is simple and quick
- Overhead of thread creation exceeds benefit
- You can achieve the same with async/non-blocking approaches
